## STAGE 5 — Next.js Rebuild
**Goal:** Production-grade product on proper tech stack
**Timeline:** After first 10 paying customers
**Status:** NOT STARTED

**Why rebuild:**
Streamlit has limitations — custom domains, authentication, performance
at scale, mobile experience, SEO. Next.js solves all of these.

**What changes:**
- Frontend: Next.js + Tailwind CSS
- Backend: Python FastAPI (reuses existing modules)
- Database: PostgreSQL (guides, users, subscriptions)
- Hosting: Vercel (frontend) + Railway (backend)
- Authentication: NextAuth.js

**What stays the same:**
- `src/transcript_fetcher.py` — unchanged
- `src/guide_generator.py` — unchanged (model-agnostic, ADR-003)
- `src/pdf_creator.py` — minor updates
- All prompts

**Done when:**
- Full feature parity with Streamlit version
- Custom domain live
- All existing customers migrated

## STAGE 6 — Chrome Extension
**Goal:** YouTube page integration — zero friction guide generation
**Timeline:** After Stage 5 is stable
**Status:** NOT STARTED

**What it does:**
User is on any YouTube video page. Extension button appears in the
Chrome toolbar. One click generates the guide in a sidebar or popup.
No URL copying required. Guide downloadable or emailable from there.

**Technical path:**
- Chrome extensions use JavaScript, not Python
- The Stage 5 Next.js app becomes a backend API
- Extension calls the API — Python code from all previous stages is reused
- Only the frontend changes

**Published to:** Chrome Web Store
- One-time $5 developer registration fee
- Much simpler approval process than mobile app stores
- Review typically takes 1-3 days

**What gets built:**
- [ ] Chrome extension manifest.json
- [ ] Content script — detects YouTube video pages
- [ ] Popup UI — guide display, download, email
- [ ] API integration — calls Next.js backend
- [ ] Chrome Web Store listing with screenshots

**Done when:**
- Extension published and publicly installable from Chrome Web Store
- Works on any YouTube video with a transcript
- Guide generates in under 30 seconds from the extension

## STAGE 7 — Progressive Web App (PWA)
**Goal:** Mobile home screen installation without app stores
**Timeline:** After Stage 5 Next.js rebuild
**Status:** NOT STARTED

**What it is:**
A PWA is a web app that can be "installed" on iOS and Android home
screens directly from the browser — no App Store or Google Play required.
Users get an app icon, offline support, and a native app feel without
the complexity of native development.

**Why this instead of native apps:**
- No Apple App Store review process (notoriously difficult)
- No Google Play submission
- No Swift, Kotlin, or React Native required
- The Next.js rebuild (Stage 5) is PWA-compatible with minimal additions
- Works on both iOS and Android from one codebase

**What gets built:**
- [ ] manifest.json — app name, icon, theme color
- [ ] Service worker — offline support, caching
- [ ] App icons — all required sizes for iOS and Android
- [ ] Install prompt — "Add to Home Screen" nudge
- [ ] Offline fallback page

**User experience:**
- User visits the site on their phone
- Browser prompts "Add to Home Screen"
- App icon appears on phone home screen
- Opens full screen like a native app
- Works even with poor connectivity (cached guides)

**Done when:**
- App installable on both iOS and Android
- Core guide generation works offline if transcript was previously loaded
- App icon and splash screen look professional
